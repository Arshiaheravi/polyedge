[2026-03-26] backend/app/services/scheduler.py [Ama] — _last_check is a module-level global shared between _poll_bets (30s) and _poll_vip_bets (5s). Both async coroutines run on the same event loop and can interleave. VIP poll writes _last_check more frequently, meaning the regular poll might use a slightly stale _last_check (from the last VIP poll run) as its reference. This is benign — the DB duplicate check (BetEvent.bettor_address + market_id + timestamp) prevents double notifications — but it could cause the same bet to be DB-queried twice. Fix: separate _last_check_vip and _last_check_default timestamps, or use a per-address timestamp dict.
[2026-03-26] backend/app/routes/alerts.py [Marcus] — POST /alerts/telegram/webhook has no secret token verification. Telegram supports setWebhook with a `secret_token` param; the backend should check `X-Telegram-Bot-Api-Secret-Token` header. Without this, an attacker who knows a valid verify code could POST a forged webhook to link their own chat_id. Fix: add `TELEGRAM_WEBHOOK_SECRET` to config; reject requests with missing/wrong `X-Telegram-Bot-Api-Secret-Token` header.
